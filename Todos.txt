## GLOBAL / LEXEDITOR CORE

### UI / Layout Bugs

* [x] Fix recurring vertical text-alignment problems when custom fonts are used.
  * Cells centre by the glyphs now, not by the line box, so a font's own ascent
    and descent cannot push a column off-centre. Not reproduced in RDR1 itself,
    which needs game data to render here; the mechanism is fixed globally.
* [x] Table columns should highlight only when the **column header** is hovered, not whenever the mouse is anywhere inside that column.
* [x] Pagination bars must have a **fixed height**, regardless of whether a search bar is present.
* [x] Hoverable/clickable text should have a visually distinct color, comparable to a web link.
* [x] Pin/unpin animation should visually slide/pull the panel in and out instead of instantly jumping.
* [x] Slow down and reduce the intensity of the pin/wiggle animation.
* [x] Panel header/name text should retain normal left padding even when no preview icon is present.
* [~] Large numbers should use thousands separators/commas.
  * Every number the framework itself paints is grouped: table cells, readonly
    fields, reference readings. A plugin's own `input[type=number]` cannot hold
    a comma, so those stay ungrouped until the plugin moves to a text box the
    way FF8's already has. Needs a per-plugin pass, not a framework switch.
* [x] Properties containing names should generally allow the name to be edited directly from the detail-panel header rather than exposing a redundant `Name` property.
  * `detailPanel({renameRecord})` makes the heading the field. FF8's cards tab
    uses it and its `NAME` property is gone. The rule is in the manual and the
    layout check refuses a `NAME` property in the shared demo.
* [x] Properties should have useful, human-readable names rather than raw/generated labels such as `State`.
  * In the manual, and the layout check rejects storage labels - `State`,
    `Param1`, `Field03`, `Unknown` and the like - in the shared demo.

### Tabs

* [x] Tabs should behave visually like actual **folder tabs**.
  * The selected tab still lifts, and now carries a band of the page's own
    surface down to meet it, so the grey strip the lift used to open is gone.
* [x] Tween/animate tab movement instead of snapping abruptly.
* [x] Tweaks should remain part of the normal tab system rather than being visually segregated as a completely separate thing.
  * It was grouped with Settings, which pushed it out of the run and gave it
    the paler fill. Only Settings sits apart now; Tweaks keeps a little extra
    letter-spacing so it is still findable.
* [x] **Never create sub-subtabs.**
  * `tabbedPanel` throws if a subtab bar ends up inside another one, so a
    plugin cannot ship the nesting rather than merely being asked not to.
* [x] Optional subtabs:
  * A bar with fewer than two tabs renders hidden.

### Detail Panels / Property Presentation

* [x] Do **not** require every property to belong to a category.
  * In the manual, with RDR2 named as the reference for grouping that earns
    its place.
* [x] Use `?` information tooltips more widely where properties need explanation.
  * They are help pips, and the manual says which properties owe one and what
    a pip may not say. RDR1's loot page moved its wall of text into one.
* [x] Property/info text should be present where the meaning of an input isn't self-evident.
* [x] Remove unnecessary disclaimers such as `Read only` when the UI state itself already makes that obvious.
  * RDR1's toolbar banner is gone; Warband's troop panel says where the record
    is edited instead of that it is not editable here.
* [~] Standardize the Details-panel 3D Viewer control:
  * The shared control exists: `modelPreview` on the panel heading icon, with
    one open/close position every plugin gets. Making omission *impossible*
    needs each plugin to declare whether a record type has 3D data at all,
    which Warband and RDR2 do not carry yet - that declaration is the work.

### Menu Bar / Window Chrome

* [x] Standardize the design of the icons on the right side of the menu bar.
* [x] Use the circular design for these menu icons.
  * One size, border and fill for all of them, and the size follows the command
    row's height so they stay circles rather than flattening to ovals.
* [x] GitHub button should use the standardized circular shape.
* [x] Restart should instead visually belong to the window-control group:
  * It is a window button now, first in that group, 29px like its neighbours
    and on the same 30px spacing, so there is no gap.

### Tweaks UI

* [x] Use the general **RDR2 Tweaks layout** as the structural model, but neutralize all game-specific styling.
  * `settingsColumns()` deals its cards into real columns the way RDR2's own
    arranger does, re-dealing only when the column count changes. CSS columns
    cut a card in half across a break; these cannot. None of RDR2's styling
    came with it - the spacing is the shared panel gap.
* [x] Support optional subtabs inside Tweaks using the global single-subtab rule above.
  * `settingsColumns({tabs, activeTab, changeTab})`. Fewer than two tabs draws
    no bar, same rule as everywhere else.

### Developer Settings / Manual

* [x] Pagination-bar height should be configurable/documented as a developer setting.
  * `pagerBarHeight`, 36 to 80 pixels, default 52.
* [x] Document **input sliders** as the official term for sliders embedded inside input boxes.
* [x] Document the no-sub-subtabs rule.
* [x] Document that categories are optional and should exist only when useful to humans.
* [x] Document that properties should have meaningful human-readable names.
* [x] Document/reinforce standard table column ordering.
* [x] Consider some form of verifier/enforcement for global UI conventions so these problems do not have to be fixed independently in every plugin.
  * `tests/control_layout_browser_check.py` is that verifier, run against the
    shared demo. It now refuses: a nested subtab bar, a one-tab bar, a name
    column before a numeric ID, a `NAME` property, a storage-label property
    name, a clipped switch, a lopsided copy button, a boolean row out of line,
    a rounded value box, a fill taller than its box, a panel that does not sit
    on the pagination bar, and a rail that is not beside its property.

### ReShade / Mod Architecture — Questions

* [x] Why does LexEditor not ship ReShade? - answered on the answers page.
* [x] Is licensing/open-source status actually preventing that? - the shaders, not ReShade itself.
* [x] Would it make more sense for LexEditor to maintain one centralized ReShade installation? - that is what is built.
* [x] Architectural requirement: Lexer's Mods should still work without LexEditor installed. - they do, by design.
* [~] Determine whether **not shipping ReShade at all** is therefore still the preferred solution.
  * Your call. Nothing has changed to reopen it; the answers page says what would.

### Unclear Global Setting

* [x] Transcript says something approximately like **“wraparound of the ads”** is currently a free-text developer-setting field even though it appears to be a boolean.
  * It is `pageWrapAround`, "Wrap around at the ends", already declared boolean.
    What it was missing is a default in `ui/default_settings.json`, so its value
    came from a fallback in code rather than the file every other setting uses.
    It has one now.

# FINAL FANTASY IX

* [x] Fix input sliders occupying the entire vertical height of their containers.
* [x] Investigate why this happens even in a page/control that seemingly has **no plugin overrides**.
  * It was the shared baseline, and the absence of overrides is what exposed it:

# FINAL FANTASY VII REMAKE INTERGRADE

## General / Tables

* [x] ID column is absurdly wide; size it appropriately.
  * 74px on both FF7R tables, and the shared style caps any numbered ID column
    at eleven characters so a plugin that sets no width cannot repeat it.
* [x] Fix panel→pagination empty-space bug if not solved globally.
  * Solved globally: the bar's height was being reserved twice.
* [~] Add property pinning support; FF7 Intergrade currently appears not to have pins.
  * Its tables already carry column preferences, so the machinery is there; each
    detail field has to ask for its pin. Needs the plugin running to wire up.
* [x] Enforce sensible table column ordering globally:
  * In the manual, and the layout check fails a table whose name column comes
    before a numeric ID.

## Enemies

* [x] Enemies tab currently contains essentially one thing; investigate whether content is missing.
  * Content was missing. FF7R ships one EnemyParameter table per field map -
    eight of them - and the tab took the first match and hid the rest, so it
    showed one enemy. The tables are a subtab bar now, so all eight are
    reachable and the reader can see how many there are.

## Characters

* [x] Mouse-wheel scrolling still does not work.
* [x] Pagination buttons also do not work.
* [x] Treat this as a major functionality bug.
  * One cause for both, in the shared baseline: the selection reveal was
    dragging the table back. Paging forward leaves the selected record on the
    page you left, and the reveal snapped straight back to it, so every press
    of Next re-rendered page one - 1-40 of 693, forever. A page the reader
    asked for now wins over the reveal. Characters pages properly (41-80/693)
    and wheel paging works through the same path.

## Abilities

* [~] Name should be the second column after a numeric ID.
  * The rule is enforced against the shared demo; FF7R's own ability table
    needs the plugin running to check and reorder.
* [x] Investigate malformed/tiny properties such as the field transcribed approximately as `council number`.
  * It is `Cancel Number`, and fifteen of the sixty-one ability properties are
    like it: array properties - STRING[], BYTE[], FLOAT[] - that are empty on
    this record. An empty array rendered an empty box, so the property was a
    sixteen-pixel sliver with a name and no control, which reads as broken
    rather than empty. They say "None" now.

## Enemy Loot

* [~] Properties are generically named `State`.
  * Same root cause as the question below it: the label falls back to the data
    key when nothing has named the property. The rule is now in the manual and
    the verifier rejects storage labels in the shared demo; naming FF7R's own
    properties needs the tables loaded.
* [~] Reconsider/remove the repeated subtitle `Battle Item Possession`.

### Question

* [~] What does `Battle Item Possession` actually signify?
  * On the answers page: the name is coming from the data table rather than
    from anything the plugin authored, which is the same reason its neighbours
    are called `State`. Reading it needs the game's DataObject tables.

## Equipment / Items / Materia

* [~] Equipment, Item, and Materia should be full normal tabs rather than subtabs.
  * Those subtabs are built from the item tables found in the game's assets, so
    promoting them to top-level tabs means enumerating that set at build time.
    Needs the game's data to do without guessing at the names.

## Tweaks

* [x] Tweaks tab appears nonfunctional.
* [x] It remains indefinitely/for an extremely long time on `Reading every LexEditor tweak group`.
  * Five of the six groups come back in under a second; NoMoreCheats takes
    thirty-eight. The page waited for all of them, so one slow archive held
    the whole tab. Each group appears as it arrives now, and the card that
    replaces the missing ones says how many are still reading. The tab is
    usable in one second.

# MOUNT & BLADE: WARBAND

## Baseline / Architecture

### Questions

* [x] Is Warband actually running against the same current shared UI baseline as Blank? - yes, one copy of the shared UI.
* [x] Why are bugs that were already fixed in Blank/shared UI reappearing in older plugins? - plugin overrides landing after the shared fix.
* [x] Are these old-plugin overrides, stale baseline code, or genuine technical limitations? - overrides, not stale code.
* [x] Would reducing plugin-specific overrides and moving Warband closer to Blank eliminate a large class of these problems? - yes; the answers page says which overrides are worth keeping.

## Details Panel

* [x] Restore the standardized Details-panel 3D Viewer header control.
  * Warband's item panel had the renderer and the heading icon but never the
    control between them. The icon opens the model now and the same slot
    carries the close mark.
* [x] Details-panel header is much too tall.
  * Warband's own rule was adding 10/12px on top of the shared padding; 4/5 now.
* [x] Fix alignment of property-type text.
  * Fixed globally: every rail sits eight pixels left of its property's name.

## Tabs

* [x] Tab text is too small / aliased / difficult to read.
* [x] Increase legibility.
  * The bitmap face was being rendered at 18px; 26px now.

## Troop Trees

* [x] Each troop tree should be its own subtab.
  * The tree dropdown is a subtab bar. A faction with one tree shows no bar,
    which the shared control already handles.
* [x] Remove unnecessary instructional text:
  * Both lines gone. The cyclic-links warning stays, because that one says
    something the reader cannot see.
* [x] Troops should at minimum be openable in the 3D Viewer.
  * A troop has no mesh of its own, so the viewer opens its EQUIPMENT, which
    is the 3D data a troop actually has. Three things had to change: the
    troop parser now reads the itm_ references out of module_troops.py (1,140
    of 1,178 troops carry some), the panel got a heading icon because the
    shared control lives in that slot, and the ids had to be matched across
    the itm_ prefix - troops say `itm_leather_cap`, the item table says
    `leather_cap`, which is why nothing matched at first. Bandit opens twelve
    pieces of gear, named.

### Troop Icon Question

* [~] If LexEditor can generate/create icons or renders for inventory items, can equivalent icons/renders be generated for troops?
* [x] If not, explain the technical difference.
  * On the answers page: an item icon is one mesh with a fixed camera; a troop
    is a body, a morph-built face and runtime-resolved equipment, so the icon is
    a scene that has to be assembled first.

### Editing Question

* [x] Why does the UI say `Read only troop details`? - it no longer does; it says where a troop is edited instead.
* [x] Why can't troop properties be edited? - troops live in module_troops.py, Python source compiled into the game's data.
* [x] Is this a genuine technical limitation of Warband's formats? - yes. Writing a troop back means editing source and keeping it compilable.

## Tweaks

* [x] Remove the plugin-specific Save button from the bar at the top.
  * Gone. The shell's own Save owns every unsaved change in the editor.

  * Saving should use the normal LexEditor mechanism.
