## GLOBAL / LEXEDITOR CORE

### UI / Layout Bugs

* [x] Fix recurring vertical text-alignment problems when custom fonts are used.
  * Cells centre by the glyphs now, not by the line box, so a font's own ascent
    and descent cannot push a column off-centre. Not reproduced in RDR1 itself,
    which needs game data to render here; the mechanism is fixed globally.
* [x] Table columns should highlight only when the **column header** is hovered, not whenever the mouse is anywhere inside that column.
* [x] Pagination bars must have a **fixed height**, regardless of whether a search bar is present.
* [x] Hoverable/clickable text should have a visually distinct color, comparable to a web link.
* [x] Pin/unpin animation should visually slide/pull the panel in and out instead of instantly jumping.
* [x] Slow down and reduce the intensity of the pin/wiggle animation.
* [x] Panel header/name text should retain normal left padding even when no preview icon is present.
* [~] Large numbers should use thousands separators/commas.
  * Every number the framework itself paints is grouped: table cells, readonly
    fields, reference readings. A plugin's own `input[type=number]` cannot hold
    a comma, so those stay ungrouped until the plugin moves to a text box the
    way FF8's already has. Needs a per-plugin pass, not a framework switch.
* [x] Properties containing names should generally allow the name to be edited directly from the detail-panel header rather than exposing a redundant `Name` property.
  * `detailPanel({renameRecord})` makes the heading the field. FF8's cards tab
    uses it and its `NAME` property is gone. The rule is in the manual and the
    layout check refuses a `NAME` property in the shared demo.
* [x] Properties should have useful, human-readable names rather than raw/generated labels such as `State`.
  * In the manual, and the layout check rejects storage labels - `State`,
    `Param1`, `Field03`, `Unknown` and the like - in the shared demo.

### Tabs

* [x] Tabs should behave visually like actual **folder tabs**.
  * The selected tab still lifts, and now carries a band of the page's own
    surface down to meet it, so the grey strip the lift used to open is gone.
* [x] Tween/animate tab movement instead of snapping abruptly.
* [x] Tweaks should remain part of the normal tab system rather than being visually segregated as a completely separate thing.
  * It was grouped with Settings, which pushed it out of the run and gave it
    the paler fill. Only Settings sits apart now; Tweaks keeps a little extra
    letter-spacing so it is still findable.
* [x] **Never create sub-subtabs.**
  * `tabbedPanel` throws if a subtab bar ends up inside another one, so a
    plugin cannot ship the nesting rather than merely being asked not to.
* [x] Optional subtabs:
  * A bar with fewer than two tabs renders hidden.

### Detail Panels / Property Presentation

* [ ] Do **not** require every property to belong to a category.

  * Categories are for human-readable organization only when they are genuinely useful.
  * RDR2's detail-panel organization is a reasonable reference even if somewhat dated.
* [ ] Use `?` information tooltips more widely where properties need explanation.
* [ ] Property/info text should be present where the meaning of an input isn't self-evident.
* [ ] Remove unnecessary disclaimers such as `Read only` when the UI state itself already makes that obvious.
* [ ] Standardize the Details-panel 3D Viewer control:

  * Header control switches/opens the Details panel's 3D Viewer.
  * Plugins should not be able to silently omit this feature where 3D data is supported.

### Menu Bar / Window Chrome

* [x] Standardize the design of the icons on the right side of the menu bar.
* [x] Use the circular design for these menu icons.
  * One size, border and fill for all of them, and the size follows the command
    row's height so they stay circles rather than flattening to ovals.
* [x] GitHub button should use the standardized circular shape.
* [x] Restart should instead visually belong to the window-control group:
  * It is a window button now, first in that group, 29px like its neighbours
    and on the same 30px spacing, so there is no gap.

### Tweaks UI

* [ ] Use the general **RDR2 Tweaks layout** as the structural model, but neutralize all game-specific styling.
* [ ] Support optional subtabs inside Tweaks using the global single-subtab rule above.

### Developer Settings / Manual

* [ ] Pagination-bar height should be configurable/documented as a developer setting.
* [ ] Document **input sliders** as the official term for sliders embedded inside input boxes.
* [ ] Document the no-sub-subtabs rule.
* [ ] Document that categories are optional and should exist only when useful to humans.
* [ ] Document that properties should have meaningful human-readable names.
* [ ] Document/reinforce standard table column ordering:
  * Numeric ID → first column.
  * Name → second column.
  * If the ID itself is a string/name-like value, Name may precede ID.
* [ ] Consider some form of verifier/enforcement for global UI conventions so these problems do not have to be fixed independently in every plugin.

### ReShade / Mod Architecture — Questions

* [ ] Is licensing/open-source status actually preventing that?
* [ ] Would it make more sense for LexEditor to maintain one centralized ReShade installation/configuration that individual Lexer's Mods add shaders/filters to?
