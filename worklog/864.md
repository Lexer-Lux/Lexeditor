# 864 — Tool Belt (DS1)

DS3-style tool belt as a DS1 tweak mod: five item boxes beneath the
start-menu strip. Issue stays `actionable`: v1 (mod 0.4.0-v1) is built,
41/41 green, dev and installed copies identical; only Lexer's live
acceptance remains (checklist below). No master commit exists for this
mod, so `untested` does not apply.

## Requirement

Five item boxes beneath the start menu's category strip. Down enters
the belt, Left/Right move between boxes, Use takes the selected item
through the game's own Use path and closes the menu, Remove clears the
box, Switch assigns the next owned eligible item, B or Up leaves. The
quick-item bar and its cycling are untouched. Five slots; eligibility
is the game's own rule (isEquip goods with Item_name_ rows, 95
snapshotted). Session-only Y assignments are fine; icons and save
persistence are deferred.

Superseded: the double-tap gesture island, hold designs, detail-pane
"Belt N" marks and the empty-belt refusal (0.2.x never accepted).

## v1 design (built)

- One E9 hook at the start-menu root update entry (0x66F4A0) into a
  data-first island: baked show flag, five slots, 95 eligible ids,
  eight UTF-16 node names, 2596 bytes of code, shared unwind template.
- Six dynamic text nodes in `category_LR`: five quantity tags under
  the strip plus the selected-name line.
- Gate: `ED6020(dialog,"R00-00")` then `("category_LR")`, so the title
  screen and closed menus run vanilla. Nodes re-resolved every frame.
- Input: live v0c button pairs (Left {89,90,9E}, Right {88,91,9D}, Use
  {B4,96}, Cancel {B5,9A,97}, Remove {A2,A4}, Switch {A3,A1}); Up/Down
  fire nothing on the root, so arrows come from GetAsyncKeyState and
  pad D-pad from XInputGetState. Edges from a previous-mask dword.
- Use calls the game's own inventory Use (0x6AE920) with a stack
  stand-in for the list dialog, after the game's own can-use check
  (0x6AECD0), then runs the root's own close sequence. Refusals play
  the back sound and stay in the belt.
- Original update runs on idle frames and for input the root ignores;
  the island returns instead only while belt arrows/Use/Cancel are
  held or edged. Show-off builds emit nothing (vanilla bit for bit).
- Owned state at exe+0x1A24C40 (16 dwords): latch, focus, box, prev,
  populated, five live ids, debug bits, last used index, frame count.

## v1a (2026-10-11): gate fix

Live: island runs (input latch fires) but the gate never opened:
looking `R00-00` up under the hook dialog always misses, because the
hook fires on the R00-00 dialog itself. v1a resolves `category_LR`
directly from the hook dialog, then the six belt nodes under it (a
chained descent vanilla uses too). Debug bits are now 1 category,
2 qty0, 4 used, 8 no-cycle, 0x10 qty-miss, 0x20 name-miss, 0x40 name;
the shared table's debug-bits row was reworded to match. Island
2574 bytes, 38 relocs; 42/42 pytest green (16 execution scenarios,
incl. a no-R00-00-level regression). Layout unchanged.

## v1b (2026-10-11): dialog-by-handle gate

v1a crashed on menu open (silent APPCRASH, fault 0xEDA1C2: the child
search derefencing a wild array). Root cause: the hook's rcx is a menu
controller, not a dialog, so ED6020 on it was never valid. v1b follows
the vanilla pattern instead: controller vtable +0x78 for a handle,
EDDFE0(handle, 'category_LR') for the dialog, ED6020 under it for the
six belt nodes. Set-text (+0xD8 arg shape) and show/hide (EDBDB0 with
a 0/1 dl) were both confirmed against vanilla callers. Debug bit 1 is
now the dialog, plus 0x80 for a good handle; the table's debug-bits
row was reworded again (its v1 rows had been pruned meanwhile, so all
four were re-added). Island 2608 bytes, 38 relocs; 43/43 pytest green
(17 execution scenarios). Layout unchanged. Awaiting the acceptance
above against 0.4.0-v1b. Crash logs saved under the session scratchpad
belt-debug/crash-esc/ (patch trio plus three WER reports).
