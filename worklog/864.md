# 864 — Tool Belt (DS1)

DS3-style tool belt as a DS1 tweak mod: five item boxes beneath the
start-menu strip. Issue stays `actionable`: v2 (mod 0.5.0-v2) is a full
rewrite of the Muse-built v1b, which Lexer reported "does nothing". 57
mod tests green; not yet seen in the game.

## Requirement

Five item boxes beneath the start menu's category strip. Down enters
the belt, Left/Right move between boxes, Use takes the selected item
through the game's own Use path and closes the menu, Remove clears the
box, Switch assigns the next owned eligible item, B or Up leaves. The
quick-item bar and its cycling are untouched. Five slots; eligibility
is the game's own rule (isEquip goods with Item_name_ rows, 95
snapshotted). Session-only Switch assignments are fine; icons and save
persistence are deferred.

## Why v1b did nothing (static, 2026-10-16)

1. Wrong item category. Inventory entry +0 is `category << 28`; goods
   are 0x40000000. v1 matched 0 (weapons), so every count read 0 and Use
   and Switch always refused. Its unicorn harness wrote goods as 0 too,
   so 43/43 tests passed on the same wrong assumption.
2. Wrong lookup. The hook's rcx is the R00-00 dialog (its only caller
   looks R00-00's own `plate_black` up on it). v1b asked
   `EDDFE0(handle, "category_LR")`, which returns a control, then
   `ED6020` on that control: it never finds a node (v1a's crash was the
   same nested search).
3. Wrong place. `category_LR` is a sub-dialog instanced by twelve menus;
   the nodes sat over the strip's help line (R04-02, y 109-144).
4. Default settings leave every slot empty, and v1 hid empty boxes.
5. Its state wrote 0x34 bytes into a 0x20-byte claim at 0x1A24C40,
   i.e. into Mana System's gauge block at 0x1A24C60.

## v2 (built, in Lexer's library, disabled)

- Layout: seven nodes in R00-00 (full screen): plate sprite
  (T02_parchment/black_plate_model) at 828,182-1177,262, the name line
  styled as `list_item/text_param_name`, five boxes styled as
  `button_item_equip/text_number` (58 wide, pitch 66, x 845, y 224).
  R00-00 has no text node, so this needed Lexeditor's new layout `from`
  (branch `tool-belt-v2`, `plugins/ds1/menu_layout.py`).
- Island: one `ED6020(dialog, name)` per node, text through `EDBD90`,
  goods names from the GoodsName bank (`[0x1C7E3E8]+0x380`, leaf
  `0x53DF10`), counts from goods entries only. Boxes read the count,
  "-" when empty, "[n]" when selected; the line reads "Tool Belt", or
  the selected item's name (or "Empty") in the belt. The root is skipped
  while focused and after leaving while a belt button is held, so belt
  input never switches categories or closes the menu.
- Use: the game's Use with a zeroed 0x2A0 stand-in (its vector pointer
  at +0x268 aimed at zeroes) and the root's close sequence; goods pass
  the can-use check unconditionally, so v2 drops that call.
- State 0x1A24E40-0x1A24E80 (declared): latch, focus, box, prev,
  populated, five ids, debug bits (1 gate, 2 box text, 4 used, 8 no
  switch target, 0x10 box node missing, 0x40 name text), last used
  index, gated frames, skip latch, frame mask.
- Composes in memory with every other library mod: 19 native
  descriptions (178 hooks) and 7 layouts.
