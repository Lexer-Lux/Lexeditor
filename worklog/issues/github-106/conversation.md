- **Recovery Duration**: vulnerable remainder in seconds.
- Their sum is the total roll length, so there is no contradictory third duration value.
- **Invulnerability Opacity**: player opacity during the invulnerable prefix (0 invisible, 100 fully opaque).

The roll snapshots the player's actual damageability and alpha, applies the i-frame state only for the configured prefix, and restores both exact prior values at the boundary or any interrupted exit. I did **not** add a fake distance setting. The resolved Story/SDK animation task surface exposes playback rate, duration, flags, start position and rotation, but no root-translation distance scale. Playback speed changes duration without changing total authored displacement. Making distance editable with the mechanisms currently resolved would mean adding velocity/coordinate/teleport writes—the exact class of workaround that previously broke this roll. That conditional part remains unsupported unless a real root-motion distance mechanism is found.

**Root cause: the roll was bound to the wrong key. Both of your reports are that one fact.**

The shipped control table, `_downloads/rdr3_discoveries/Controls/README.md`:

```
:480  0xDE794E3E  INPUT_COVER  Q      RB
:481  0x06052D11  INPUT_DIVE   Q      RB
:563  0xD9D0E1C0  INPUT_JUMP   Space  X
```

The roll initiated on `INPUT_DIVE`, and INPUT_DIVE **is** the Q key — the same physical button as Cover. So:

- **Q rolled** because Q was literally the trigger. Not a side effect and not the binocular flag from last time — the trigger itself.
- **Space could never roll**, with a knife, a gun, fists, aimed or not, because nothing in the roll module read `INPUT_JUMP` at any point. That is why the weapon in your hand made no difference: no weapon test was ever reached.

Your own log states both halves. The two rolls that did fire name the Q path:

```
+69453ms [roll] engine combat-roll predicate edge controls=0,0,0,0
                pair=combatroll_fwd_p1_00/combatroll_fwd_p2_00
                trigger=dive-press-initiated activeStage=0
```

and every heartbeat in that session reads `engineCombatRoll=0`, so the game itself never starts a roll on foot either — nothing was ever going to answer a Space press.

**What changed**

The roll now triggers on `INPUT_JUMP` (Space / X). `INPUT_DIVE` is no longer a trigger anywhere in the module, so **Q cannot roll**. That key is also the sanctioned one: when Rockstar wants this move gone it disables jump and dive together, back to back — beat_drunk_dueler.c:7949-7950, sadie3.c:37047-37048, mudtown3b.c:57927-57928. The vanilla jump is suppressed on the same frame with Rockstar's own call, so one press gives one roll rather than a jump plus a roll.

Space is also jump and climb, so the roll only takes the key under the combat-mode rule you wrote in Lexer-Lux/Lexeditor#284 — details there. Climbing, ladders, mid-air, ragdoll, vehicles, mounts and swimming all keep the key, so ordinary traversal is untouched.
