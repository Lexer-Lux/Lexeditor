# Worklog: 078 Class A Batch 59 193 11 116 170 1 195 2026 08 04

## Class_A batch: #59, #193, #11, #116, #170, #1, #195 — 2026-08-04

Built clean, installed. Five of the seven had a single concrete cause found by
reading the code or the artifacts rather than by theorising.

**#59 campsites.** Key moved to VK_F3 and made ini-configurable
(`[Campsites] Key`, parsed base-0 — `GetPrivateProfileIntA` stops at the `x` in
`0x72` and silently returns 0, so the value is read as a string). The globals
`g_f4*` are now `g_campKey*`.
Respawn: the old code teleported on the `!dead && wasDead` edge, one frame, once.
`PLAYER_DEAD` clears BEFORE Rockstar finishes its own respawn placement, so that
placement overwrote ours. Replaced with a held window
(`g_campRespawnActive`, `RespawnWindowMs`, default 15 s) that requests collision
at the target and re-asserts position every frame until collision is loaded,
control is back and the screen is not faded — then places the horse, materializes
the camp and releases. Also messages the player on death when no campsite is
placed or none is activated; silence there was being read as "feature broken".

**#193 icons.** Not a registration problem this time — that was last session's
fix and it held. `prepare_inventory_dds.py` wrote each source PNG through at its
native size: casings 512x512, bottle and materials **1254x1254**. 1254 is not a
power of two, which a DXT5 RAGE texture must be, and the dictionary was 11 MB
uncompressed for 17 icons. Normalised everything to 256x256 (`ICON_SIZE`);
dictionary is now 1.15 MB, verified to still contain all 17 texture names and a
valid RSC8 v16777218 header matching the working third-party PDOR_ICONS.ytd.
Separately, `build_inventory_ytd.ps1` installed only to `MyOverhaul\stream` —
the per-mod folder Worklog #147 already proved LML never reads — so every future
rebuild would have been a silent no-op in game. It now also writes `lml\stream`.

**#11 stamina.** System was already built; the open part was Lexer's question.
Added `playerMovementStaminaMode` / `horseMovementStaminaMode` so the mode name
and the rate cannot disagree, plus `[HumanStamina] ShowMode=1`, an on-screen
readout of mode, applied rate, bar, core and speed for player and mount.
Recorded honestly that horse gaits are speed bands, not a gait state — the engine
exposes no gait flag — so a downhill trot can read as a canter.

**#116 binoculars.** `equipBinoculars` passed `TRUE` as the third argument to
`SET_CURRENT_PED_WEAPON`, the "force straight into hand" flag, which bypasses the
draw task. That is the whole bug; the zeroed trailing flags the ini comment
credited for preserving the vanilla transitions never got a chance to apply.
Now `g_binocularsInstantEquip` (default false), with `DrawMs`/`StowMs` replacing
the hardcoded 650/700 ms windows, and the stow-side restore animated too.

**#170 prone movement.** Movement was root motion only. The three crawl clips
carry very different authored displacement — `walk` almost none, `walk_turn_l4`
/`walk_turn_r4` a large sweep — which is exactly "forward does nothing, every
other direction slides rapidly". Nothing capped it while moving; velocity was
only zeroed on no-input, so authored travel stacked on residual momentum, and
the per-frame `SET_ENTITY_ROTATION` from ground alignment was fighting the mover
as well. Replaced with an explicit velocity drive along facing at
`[Prone] CrawlSpeed` (0.85 m/s), scaled by input magnitude and by
cos(heading error) so turning does not launch him sideways, re-applied every
frame so it is self-capping. Clip is now cosmetic with cadence following speed.
Underwater: `IS_PED_SWIMMING` only trips once actually swimming, so it never
covered water shallow enough to stand in. `proneHeadWouldSubmerge` compares
`WATER_HEIGHT` against `GROUND_Z` + `WaterHeadClearance` (0.30 m) and refuses
entry, and runs the authored exit if he crawls into deeper water.
Trace now logs `drive=` (commanded) and `moved=` (actual metres since last line)
so the next test distinguishes "we asked for nothing" from "the world ignored us".

**#1 core reserves.** One root cause in two places: a size heuristic. CoreClock's
loop accepted any drop bigger than one point as a legitimate scripted penalty.
On-foot core spends are one point at a time and were caught; swimming spends fast
enough that a single sample sees a multi-point drop, which was accepted — the
swimming leak. The horse guard additionally required `horseSprintHeld` and
re-baselined `protectedHorseStaminaCore` every frame it was not exhausted, so any
spend at a canter/gallop/swim/jump was both missed and then adopted as the new
protected value, permanently disarming the pin.
Now: while an outer bar is at or below `[NoReserveCores] BarFloorPercent` (10%),
any fall in the matching core is refused outright — no size test, no held
control. Horse re-baselining only happens above the low band. Documented
trade-off: a genuine scripted core penalty landing while the bar is empty is also
refused, which is the correct priority for this item.

**#195 prone weapons.** Did NOT re-enable `customBackRigEnabled` /
`customOneHandAimEnabled`; the Worklog entry above records that doing so
reproduces the full-body build already rejected in-game, and the reference mod
has no continuous prone aiming to port. Implemented instead the one mechanism
that entry names as untried: `[Prone] GroundedAimMode=1` carries a one-handed
weapon into prone, allows wheel selection, and holds the authored
`ai_combat@aim_sweeps@cowboy@grounded@base@1h` loop as a SECONDARY upper-body
task (flags 0x10000430, +0x20 over the usual full-body 0x10000410) WITHOUT
clearing tasks, so the native aim task keeps driving the gun at the reticle
underneath. Default 0 so it cannot contaminate the #170 movement test. If the
gun still fails to track in mode 1, one-handed prone aiming needs custom
animations and the item can close with a real answer.
