# Worklog: 021 204 205 206 Weapons Tab Fixed 2026 08 05

## #204 / #205 / #206 Weapons tab — fixed 2026-08-05

#204 scroll reset: `renderWeapons` rebuilt `#main` on every selection without
carrying the list scroll. Applied the `renderLoot` pattern verbatim — capture
`document.querySelector(".loot-list")?.scrollTop` before building the list,
restore it after the `lootsplit` is appended.

#206 root cause, and it also fixes #205's data problem: `_weapon_rows` in
`server.py` builds a field name by joining XML tag names, and every repeated
list element is literally `<Item>`. WEAPON_BOW therefore produced twelve rows
all called `DamageModes/Item/Damage`, twelve called `.../DamageType`, and so
on. `weaponDetail` keys its V and WR reference maps by field name
(`byField`), so all twelve collapsed onto the LAST entry — `DM_ARROW_WOUND` —
which is why every mode's reference read as wound and every value looked
changed.

Fix: `_weapon_rows` now labels a list element with its own `Name` when that
name is unique among its siblings (falling back to `Item N`, then `Item`). Rows
read `DamageModes/DM_ARROW_FIRE/Damage`.

Verified through the real API on an isolated server (port 8790; Lexer's own
instance on 8765 was left alone):
- WEAPON_BOW: 393 rows, 393 unique field names (was 206 unique).
- All 170 records in both `mine` and `vanilla` have zero duplicate field names.
- Diffing every bow field against vanilla through the API: exactly ONE differs,
  `WeaponFlags`. That is #199, not #87. No damage value on the bow is modified.

`weaponBig6` no longer hardcodes `DamageModes/Item/Damage`; it takes the first
`DamageModes/*/Damage`, i.e. the weapon's default load, and says so in the tile
hover.

#205 hovers: `weaponValueControl` set a `title` on every control that only
described the control ("Constrained to N values...", "Numeric scalar stored
directly in weapons.ymt", "Open identifier/hash field..."), and `weaponDetail`
piped that into the field-name `?`. All three titles removed. New
`WEAPON_FIELD_HELP` map (~100 leaf field names: damage modes, headshot ramps,
fire rate and reload, ranges, force, bullet-bending aim assist, sway, recoil,
camera FOV) plus `weaponFieldHelp`, which trims the leaf off linked ammo rows
("WEAPON_BOW / Performance / Damage") and returns "" when nothing is known, so
no `?` is rendered at all. `UNK_MEMBER_*` fields get an explicit
"unnamed in the extracted schema, editing it is a shot in the dark".
