## #169 (a)(b)(e)(f) / #85(a) / #113(d) — 2026-08-05

#169(a) limb clipping. `resolveClimbProbes` returned the CENTROID of the hit
points (`cvMul(points, 1.0f/hits)`), and `attachClimbPhysics` stands the body off
that plane by `g_climbSurfaceOffset`. On a convex/irregular face the centroid
plane lies INSIDE the protruding geometry, so the body sits too close and any
limb over the bulge penetrates. Averaging is only correct on a flat wall, which
is why flat surfaces never showed the bug. FIX: keep the averaged normal for
orientation (stable pose), but take the standoff distance from the MOST
PROTRUDING contact - project each qualifying hit onto the fitted normal, take the
max, and push the returned point out by that much along the normal, clamped at
>= 0. Deliberately does not move the point ALONG the face, so he does not slide
sideways onto whichever bump won.

#169(b) lateral. RE-VERIFIED the CODEX claim rather than repeating it: it was
WRONG. The game ships `mech_loco_m@character@arthur@terrain@unarmed@narrow_ledge`
plus `_blizzard` and `_cliff` variants - a purpose-built ARTHUR narrow-ledge
locomotion set. What was in use is `script_story@fus1@ig@ig_1_cliffsidetraverse`
clip `cliff_p1_walk_loop_player`, a story cutscene of a different character.
RDR2 script has no SET_PED_MOVEMENT_CLIPSET usage (only
RESET_PED_WEAPON_MOVEMENT_CLIPSET appears anywhere in script_rel), so terrain
locomotion is engine-driven and the set must be played as an anim dict.
The clip names inside it are undocumented. Rather than guess - the exact failure
mode behind #98, #112 and #182 - the code REQUESTs the dict, then tries
{walk, walk_loop, move_walk, shuffle, idle} in order and keeps the first for
which IS_ENTITY_PLAYING_ANIM returns true, logging either the winning clip or
"dict loaded but no candidate clip played". Falls back to the story clip.
CODEX corrected.

#169(e) reverse-mantle. `midairGrab` required `pushing` (moveY < -0.35, steering
INTO the face) and probes only ever fired along `climbScanDirection`, i.e. the
way he faces. Walking off a ledge puts the surface BEHIND him, so no probe could
ever see it. Added `g_climbScanReverse` (flips the probe direction),
`lastGroundedAt` / `justSteppedOff` (airborne within 420 ms of being grounded),
fired the batch backwards during that window, and let `justSteppedOff` satisfy
midairGrab on its own.

#169(f) summit clipping. The mantle arc was already a quadratic Bezier with
control z = max(from.z, target.z) + 0.35. A quadratic Bezier does NOT pass
through its control point - it peaks at half the control's offset from the
chord - so the intended 0.35 m of lip clearance delivered ~0.17 m. Doubled at
the use site and made tunable: `[Climbing] TopOutClearanceMeters`, default 0.45
(so 0.90 control offset).

#113(d) plants — NOT DONE, and honestly so. `updateReconTagging` scans peds via
NEARBY_PEDS/worldGetAllPeds only; plants are world objects. `worldGetAllObjects`
exists in the SDK (main.h) so enumeration is available, but identifying which
objects are harvestable plants needs their model hashes, and those are not
established anywhere in this project yet. Guessing model names is precisely the
failure that made #98, #112 and #182 silently do nothing for months. NEXT STEP:
a plant-model identification pass (loot_table_herb.meta / catalog herb items ->
world object models), then filter worldGetAllObjects on that set and reuse the
existing marker path.
