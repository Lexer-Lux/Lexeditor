#1 swimming reserve — the real hole. `onFloor` protection required
`GET_STAMINA_BAR(player) <= g_reserveBarFloor` (10%). Swimming drains the bar
fast enough that one sample can observe a MULTI-POINT core drop while the bar is
still above the floor, and the `live < managedCore - 1` branch deliberately
accepts multi-point drops as genuine scripted penalties. So the swim spend was
allowed through at any bar level above 10%. FIX: `IS_PED_SWIMMING(ped)` now also
satisfies `onFloor` for core 1, protecting the Stamina core at any bar level
while in water. Nothing else spends a core that fast, so it costs nothing on
land. (The "reserve ALWAYS" half was the #203 oscillation.)

#169(d) slide-into-climb — it WAS implemented (`setClimbState(Grabbing,
"vanilla_sliding"/"detected_slipping")`) and could never fire for the reported
case. `maybeSlipping` REQUIRED `pushing` (moveY < -0.35, i.e. holding forward
into the slope), but an uncontrolled slide is precisely when you are NOT driving
into the hill, and `_IS_PED_SLIDING` (0xD6740E14E4CEFC0B) does not reliably
report a slope slide. Added `carriedDownhill` — grounded, velocity.z < -0.30 and
horizontal speed > 0.35 — as an independent trigger; `pushing` now only loosens
thresholds instead of gating the whole test.
