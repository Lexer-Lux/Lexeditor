# PR #489 Warband completion acceptance

This handoff separates code, rendered UI, candidate and installed-game evidence.

## Code evidence

- All 33 Warband Data Map rows have an explicit capability regression.
- Structured Module System saves preserve record IDs and unmodeled fields, reject
  stale source and duplicate IDs, create backups and replace atomically.
- Raw source saves now also use a source hash, stale-write refusal, backup and
  atomic replacement.
- Helper-generated records are not treated as literal tuple records. Public
  Persistent World particle records using psys(...) are therefore source-only.
- Installed module discovery is based on each module.ini, not optional manuals.
- The game-inspired CSS theme contains no game artwork. Installed Warband font
  data is read locally into the user's private cache; no TaleWorlds font or sound
  asset is committed.

## Rendered evidence

tests/warband_browser_check.py renders the real Warband HTML/CSS/JS at 900x620,
1200x800 and 1600x1000. It checks fitted Data Map paging, structured Misc.
controls, loading/empty/error states, table/detail edits, Discard, Save/build,
navigation away and reopen, Items, preview fallback and troop trees. A passing
browser fixture is rendered evidence only, never in-game acceptance.

The WSE2 helper browser fixture separately checks the shared Home helper panel
and explicit Install/Repair action. Unit checks cover package integrity,
transaction rollback and launch ownership.

## Isolated candidate boundary

Never use C:\Lexeditor as a disposable candidate. Stage PR #489 in a separate
Windows directory such as C:\Lexeditor-candidates\warband-pr489, verify that
checkout is on codex/warband-plugin-completion, run
tools\Warband-checks.cmd --checks-only, then launch that isolated checkout with
the normal Lexeditor environment.

A source checkout is staging, not proof that a packaged/runnable candidate has
been delivered. This agent runtime has no mounted Windows game/install tree, so
candidate execution remains a separate Windows acceptance step.

## Installed-game acceptance

1. Confirm Home detects the actual Steam Warband install and lists every module
   containing module.ini, including a module without info_pages.txt.
2. Open the real project and verify the locally derived Warband font and real
   item previews; missing assets must degrade without breaking editing.
3. Audit Map in the installed project. Scripts, triggers, dialogs and animations
   remain Source only; BRF/DDS remain read-only; generated output must not claim
   structured editing.
4. In a disposable project copy, edit a literal structured record, Save/build,
   reopen and confirm persistence. Make another edit, Discard, reopen and confirm
   the discarded value never reached source.
5. Open a helper-generated record from a real mod and confirm it is source-only
   with no structured write.
6. Press Play for the intended installed module. Confirm a real Warband window
   appears and the selected module loads.
7. If WSE2 is used, perform explicit Install/Repair, verify the pinned install,
   launch it, and check Steam overlay/controller behavior. Stop must affect only
   the Warband job Lexeditor launched.
8. Record screenshots/logs and the exact accepted commit. Do not promote static,
   fixture or CI evidence into this installed-game section.
