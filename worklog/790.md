Elden Ring-style spell slots as a DS1 tweak mod. Issue stays `actionable`:

## Design (verified statically)

One 315-byte stateless island replaces the slot-count function entry at
RVA 0x2DFA90 (six original bytes: REX-prefixed push plus stack reservation,
jump plus NOP pad). The island ignores the Attunement stat and returns
min(maximum, base + stones * perStone + effect bonus), calling the game's
own inventory finder at 0x74E860 for the held quantity of goods 9015 and
the game's own effect-bonus getter at 0x404060 when effects exist so the
Seance Rings keep working. Settings: baseSlots 0-12 (default 2), perStone
1-3 (default 1), maxSlots 1-12 (default 12), keepRingBonus (default on);
base clamps to maximum at build time.

Verified anchors: the slot function reads [rcx+0x48] and compares upper
bounds 9..49; 0x404060 sums the u8 at [row+0x142], which is SpEffectParam
`changeMagicSlot` (offset 322) read from the installed params; vanilla
users are effects 2040/2310 (+1 rings) and 50 (+3). `changeMiracleSlot`
(+0x143, effect 2982) has no inspected summing caller and is probably
vestigial. EquipMagicData holds 12 eight-byte entries from +0x18 with the
selected index at +0x78.

## Placement dependency (for #682)

Stone pickups need per-map events in `event/*.emevd.dcx` (67 files: one
`.emevd.dcx` plus one `.emeld.dcx` per map, plus common files). Open tooling
already reads and writes them: SoulsFormats handles EMEVD and MSB1 for
DSR (used by current DSR mod projects for event edits), and Darkscript3
with Mattscript edits the scripts in readable form. Per the research-first
rule, #682's Areas work should start from these, not new parsers.

Open questions for whoever takes it: whether pickup positions live in the
event args or MSB regions; per-event merge semantics for the loader (the
param merge is the model); which flag range stone pickups should use so a
later change can keep their orbs gone on NG+ too. Nothing in this mod
constrains those choices: the island counts goods 9015 however it arrives,
and the guard refuses duplicates however they are given.
2. In-game acceptance (offline): status-screen count, attune-menu
