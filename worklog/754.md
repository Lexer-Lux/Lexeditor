# 754 — Favorite / Protected Items (DS1)

Elden Ring-style favorite system as a DS1 tweak mod. Issue stays
`actionable`: slice 1 is lab-verified, the native slice is designed with
grounded leads but unproven.

## Requirement

Mark eligible inventory/equipment items as favorites with a gamepad
shortcut; show a mark in inventory/equipment/shop interfaces; refuse
sale/discard of protected items until protection is removed; filter or
sort favorites where practical. Covers weapons, armor, rings,
consumables and other sensible categories. Vanilla behavior when
disabled.

## Static findings for slice 2

- Lists are cell templates (`list_item`, `S02_list_item`,
  `S06_list_cell`); per-row marks need a native cell-fill hook.
- Equipment fill 0x642940 sets row text via 0x647990; 80+ equip-table
  reader sites mapped (fields +8/+0x10/+0x14); dialog-name use sites at
  0x6B84A5/0x639291/0x72DD13/0x6B87CA.
- Input chain: XINPUT1_3 ordinal 2 (GetState) via stub 0x82F790, six
  call sites; the poll routine stores the raw wButtons word at
  device+0x260 (0xE280B1). Combat pad writes mapped (0x84 R1, 0x85 L1,
  0x89 R2, 0x97 L2, helpers 0x8B/0x98/0x99/0x86/0x87/0x92, flags
  0x1C4, queued 0x224). Face-button pad bytes NOT mapped: no LEA refs
  to MenuCtrl strings, no pointer table, `test imm` absent from poll
  code, disp-0x260 scan too noisy, 0x1A4xxx button getters live in a
  region whose on-disk bytes differ (see codex ammunition-hud).
- `ui_flags` 0x71AC10 aggregates ~17 sub-checks into bits (0, 2, 3, 4,
  5, 6, 7, 9, 0xA, 0xB, 0xC, 0xD, 0x13, 0x14, 0x1B, 0x1E...); casting
  mask ignores bits 7/11/19/31. Which bit means "equipment menu open"
  is unmapped.
- Still unmapped: face-button pad bytes, menu-open bit, selected-row
  to inventory-index mapping, flag storage (save bits vs sidecar),
  sell and discard paths, filter/sort. See the mod `sources.md`.
