# 754 — Favorite / Protected Items (DS1)

Elden Ring-style favorite system as a DS1 tweak mod. Issue stays
`actionable`: slice 1 is lab-verified, the native slice is designed with
grounded leads but unproven.

## Requirement

Mark eligible inventory/equipment items as favorites with a gamepad
shortcut; show a mark in inventory/equipment/shop interfaces; refuse
sale/discard of protected items until protection is removed; filter or
sort favorites where practical. Covers weapons, armor, rings,
consumables and other sensible categories. Vanilla behavior when
disabled.

## Live session 2026-10-10 (game crashed twice, probing stopped)

Two game processes died during read-only probing (183768 between
samples, 178336 during enumeration attempts). The probes only use
OpenProcess, ReadProcessMemory, snapshots and CloseHandle: no writes,
injection, breakpoints or game-code calls, so they should not be able
to crash the game, but the cause is unproven and the F: install runs
Lexeditor's loader with an applied patch. No further live reads without
Lexer's explicit say-so.

Findings before the crashes:

- menu+0xC2C reads a constant -1/60 with the menu closed, the menu bar
  open and the equipment menu open: dead as a menu flag.
- Menu-singleton 4 KB diff over the same three states: 4 bytes of what
  looks like an animation timer. No clean open/closed flag there.
- `ui_flags` inputs funnel into query 0x71ABD0, which reads a static
  .data array (identical across processes and menu states): nearly the
  whole ui_flags bitmask is constant. Menu-open state is not in the
  globals sampled so far.
- VirtualQueryEx and heap snapshots are refused (error 5) on the game
  process from this runtime; ReadProcessMemory and module snapshots
  work. A full-memory differential button scan is therefore not
  possible here; the CE capture recipe above still stands.
- `ui_flags` 0x71AC10 fully reversed: every input funnels into query
  0x71ABD0 over a static .data array plus static bytes. The bitmask is
  effectively constant; it cannot detect menus. Menu singleton
  +0x0..0x4000 diffed open vs gameplay: zero state bytes (4 timer
  bytes only). Menu-open state lives in heap dialog objects,
  reachable only via enumeration (CE) or a static chain not yet found.
- Frame input 0x396860 sits in vtable 0x132F1E0 (no RTTI, no LEA
  constructors found); poll routines have no direct callers or LEA
  refs. Static pad/device chains remain unmapped.
- Sell-path survey: shop cell fill 0x6CEFC0 (1454 bytes, find-child /
  set-text / set-visibility call shapes confirmed for island reuse),
  called once from row controller 0x6CF7DF; controller 0x6CF680 is a
  script event dispatcher (event ids 0x3EF, 0x992, 0x993, 0x998,
  0x1329) with no inventory reads. No direct quantity-write sites
  follow any imul-0x1C reader, so removal goes through a shared
  routine; the sell commit and discard handler are still unmapped and
  are best found dynamically (CE "what writes" during a sale).
- Inventory entry struct (grounded, 0x6465A0 and accumulator 0x747470):
  +0 category tag compared by exact equality against exactly four
  values (0, 0x10000000, 0x20000000, 0x40000000), +4 item id passed to
  per-tag resolvers, +8 quantity. Tag 0 uses native resolvers
  0x5357D0/0x532B20, tag 0x10000000 uses 0x531460/0x52EB90, tag
  0x20000000 uses message-bank table 2, tag 0x40000000 uses table 3.
  Resolver validates index against count +0x130 and split +0x140,
  then imul-0x1C plus table +0x150/+0x158. An island mirrors these
  ~15 instructions to resolve slot to (tag,id), which is exactly the
  model's stable identity with kind standing in for the tag.
  Tag-to-kind mapping VERIFIED live against bank row sets: 0 is
  weapon (bank 0, 1245 rows incl. ammo; id/100*100 stage-2 lookup),
  0x10000000 is armor (bank 1, exact 324-row match), 0x20000000 is
  ring (bank 2, exact 41-row match), 0x40000000 is goods (bank 3,
  272 rows incl. rows the editor hides). Banks 4 (469 rows) and 5
  (17 rows) hold reinforcement multiplier floats for the stage-1
  resolvers. The mod model now carries TAG_FOR_KIND with a test
  (20/20 green); the island mirrors from_entry exactly.

## Slice 2 design (paper, unproven)

Shape mirrors better-casting plus the `exe_patches` spec v2:
`script/favorite_x64.S` (`{name}` placeholders) assembles via
Keystone into `CODE` hex + relocations in `script/native_patch.py`;
`build()` emits `native/favorite-items.json`; disabled emits
nothing (vanilla bit-for-bit, as slice 1). One code island with an
entry offset per hook, one data island (flag array, baked sidecar
path, star string); function entries + unwind info copied from
better-casting's template. Hook overlap is a hard Apply error
(`_layout`: "both patch the instruction"), so 754 must avoid every
RVA another tweak owns — notably better-casting's 0x39761A.

- Toggle poll: frame CALL 0x397667 (call 0x391300, bytes
  e8949cffff; genuine CALL, target has .pdata), backup 0x39690E
  (call 0x391370). Both verified by disassembly; no overlap with
  the owned native hooks (0x2DFA90 attunement, 0x39761A casting,
  0x24FCFB/0x397412 binoculars). A no-op skeleton island for
  0x397667 passes Keystone assembly, `validate()`, `compose()`
  onto the installed exe (confirmed pinned vanilla by its SHA),
  branch-to-island landing, and combination with
  better-casting's spec (probe_754_skeleton.py: SKELETON PROVEN).
  Polls the face-button byte (TBD, DInput path: no
  XInput on DualSense), the menu-open detector (TBD) and the
  selected-row to index map (TBD); edge-detect Y/Triangle,
  toggle (tag,id), write the sidecar.
- Row marks: equip fill 0x642940 (text via 0x647990), shop fill
  0x6CEFC0 (find-child/set-text confirmed), inventory fill TBD.
  Mirror the ~15-insn resolver (0x6465A0 shape) to (tag,id),
  linear-scan the 64-entry array, append " ★" through the same
  set-text call (encoding TBD, likely UTF-16). Spec-v2 hook
  relocations keep these hooks to a string/call patch.
- Sale/discard guards: sell commit and discard handler TBD (live
  "what writes" during a sale). Resolve identity; if favorite,
  skip the commit and say so through the game's own message box
  (routine TBD).
- Identity (tag,id) with TAG_FOR_KIND verified live
  (0/0x10000000/0x20000000/0x40000000 =
  weapon/armor/ring/goods).

Persistence is a sidecar: saves are off-limits per Lexer. One
fixed 520-byte file (magic, version, count, 64x(tag32,id32));
`build()` bakes the path into island data; missing or corrupt
starts empty, never crashes. The island resolves kernel32 via a
PEB walk (ASLR-safe), lazy-reads on first use, writes on toggle
only. Fallback: session-only memory (weak; only if island file
I/O proves flaky).

Tests mirror better-casting: Keystone rebuild round-trip,
relocation application, `validate()` green, (tag,id)
scenario tests, ground-truth original-bytes checks.
