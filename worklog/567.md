# #567 — Open games without a mod in locked vanilla view

## Requirement (issue + Lexer's 2026-09-24 correction)

- No mod yet is ready, not a warning. It opens on the game's vanilla source,
  locked, with no project behind it: no placeholder project and no copy of
  `template_root`.
- A chosen mod whose folder has gone, or a damaged mod, keeps its warning.
- Read-only is enforced for every plugin, in the shared UI and in the service.
- Creating or choosing a mod from the menu reopens the editor on it, unlocked.

## Implementation (branch `claude/admiring-hamilton-9m6zdg`)

- `project_manager.py`: `snapshot()["vanilla"]` is true when no mod was ever
  chosen and the default folder does not exist. That folder is not listed as
  a mod. `forget()` on the open mod clears `current`, which returns the game
  to vanilla.
- `desktop_host.py`: Home rows carry `noMod` and stay ready. `open_plugin`
  passes `LEXEDITOR_VANILLA=1` and `LEXEDITOR_MOD_READ_ONLY=1`, plus the
  project variable naming the absent folder. `vanilla_session()` tells the
  shell.
- `plugin_http.py`: `PluginRequestHandler.__init_subclass__` wraps every
  plugin's `do_POST/PUT/PATCH/DELETE`. In a vanilla session they get 403
  unless the route is in `READ_ONLY_SAFE_ROUTES`. Bannerlord, Chrono Trigger
  and RDR2 now subclass it, so no service is left unguarded. Managed-mod
  locks (`LEXEDITOR_MOD_READ_ONLY` without `VANILLA`) keep each plugin's
  narrower lock, so FF7R's managed mod still deploys.
- `ui/framework.js`: `mountShell` asks `vanilla_session`, ORs it into
  `readonly`, and so disables Save and refuses edits through the existing
  capture guard. It labels the mod menu "🔒 Vanilla · Add a Mod or Find a
  Mod", shows a toast, and switches plugins that declare a `vanilla` project
  source to it. `ui/chooser.html` hover text says it opens the unmodded game.
- Per plugin, with no mod folder:
  - Stardew: installed/unpacked data with empty patches.
  - Factorio: the game's own `script-output/data-raw-dump.json`, from the
    game folder or `%APPDATA%\Factorio`. That dump location is from general
    Factorio knowledge and has not been confirmed on Lexer's install.
  - Palworld: no package and no PalSchema patches.
  - Project Zomboid: the game's `media/scripts`.
  - Terraria: empty build.txt view.
  - DS3: already falls back to `Game/Data0.bdt`.
  - FFX/X-2: already reads the VBF archives.
  - FF7 Rebirth: see gaps.

## Evidence (agent-side only)

- `tests/test_vanilla_without_mod.py`: snapshot and Home status, open locked
  then create unlocks, service refusal, every server guarded.
- `tests/test_vanilla_plugins.py`: per-game vanilla reads that create
  nothing.
- `tests/test_vanilla_shell_lock.py`: headless browser check of the shell
  lock.
- None of this is rendered-UI or in-game acceptance. No game data was
  available in the cloud container.

## Gaps / next work

- FF7 Rebirth: vanilla PlayerParameter exists only in a mod's extracted
  `source/`. With no mod the page says so. A shared vanilla extraction is
  needed to show values.
- FF8, FF7, FF9, RDR1, RDR2, Warband, Bannerlord, Chrono Trigger and FF7R
  servers import without creating the folder. Their read routes with an
  absent project are unverified without game data. Plugins with a Vanilla
  source are switched to it by the shell.
- "Add a Mod" still copies `template_root`. For FF8, RDR1, RDR2 and Warband
  that is the user's existing mod (Warband's is 3.9 GB). A real empty
  starter per game is still needed.
- Launching a game from a vanilla session passes the absent folder to game
  controllers that take a project.
- Lexer check: open a no-mod game from Home and confirm vanilla values, a
  disabled Save, and that Add a Mod unlocks it.
