## Verified leads from the private executable

Addresses below are RVAs, relative to the loaded module, not file offsets.
The preferred image base is 0x140000000; use the PE section table on disk.
Settled slot/table/cache facts are in `codex/ds1/ammunition-hud.md`.

- 0x678CD0 computes the native ammunition icon/count for a HAND. It reads
  selected-ammunition indices, not an independent primary/secondary pair.
- 0x678A00 updates count children `text_arrow_number00`/`01`, with cached
  values at widget+0x22C/+0x230. Reusing one object for both slots shares its
  cache and can suppress one of the updates.
- 0x31B750 reads equipment item IDs by raw slot; arrows are 4/6, bolts 5/7.
- 0x747860 and 0x747920 resolve selected ammunition through an inventory
  index table and a 0x1C-byte entry stride. They return -1 for missing data,
  which must not be conflated with a real zero quantity.
- The image contains `Ins_F20-00_arrow_l`, `Ins_F20-00_arrow_r`,
  `F20_01_arrow_change`, and `menu:/menu.drb`. These are native HUD leads,
  not proof that cloning a node alone supplies an independent binding.
- Input hook site 0x396EAE matches the public GyroAim source. However, the
  supplied on-disk bytes at logical-input helpers 0x1A4140/0x1A41F0 differ
  from that source's live-code guards. Do not copy live offsets into an
  on-disk patch and assume the instructions match.

No executable, disassembly dump, memory dump, game archive, or source asset is
committed. The private file has not been changed. A targeted Library search
found the executable, but not the native menu layout or player state-machine
archive.

## Implementation route and remaining work

1. The explicit four-slot reader, synthetic tests and pinned read-only probe
   are implemented; actual in-game observations still need validation.
2. Trace the exact shot-time ammo selection and consumption path, including
   actor/equipment synchronization and bow draw/release. A frame-level R2 to
   R1 substitution alone is insufficient evidence. Do not reset ammo on
   button release before a pending shot consumes it. Preserve melee, magic,
   menus, left-hand equipment, and remapped keyboard/controller inputs.
3. Inspect the installed `menu` layout (`menu.drb` or its compressed form)
   and native widget creation/ownership. Duplicate a native ammo widget with
   independent binding, quantity cache, placement and teardown. Validate
   both bow and crossbow display, not just that a second node exists.
4. Prefer Hext and existing game routines. A runtime loader, safe enable /
   disable ownership, and standard shared tweak control are still required;
   the current DS1 deployment only owns the parameter archive. Do not hide an
   unimplemented patch behind an enabled checkbox or modify param deployment
   as though it already owns the executable.
5. Recheck exact build guards after loading; run synthetic preservation / ABI
   tests, CI, and then real in-game acceptance. Do not infer gameplay success
   from a green unit test. No merge or master push is authorized.

Human acceptance eventually needs distinct primary/secondary arrows and
bolts, R1/R2 alternation and consumption, empty/exhausted slots, held/released
bow input, weapon/hand switching, reload/death transitions, HUD scaling and
overlap, and disable restoring vanilla. This is not a request to run those
checks now: there is not yet a delivered playable candidate.
