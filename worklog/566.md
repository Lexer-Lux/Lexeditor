# #566: Make the interface usable with a controller

[Live GitHub issue and comments](https://github.com/Lexer-Lux/Lexeditor/issues/566)

## Requirement

The whole interface works with a game controller and no mouse or keyboard, with
a visible focus highlight, because the Steam Deck download (#496) depends on
it. Build it once in the shared UI, not per plugin.

## Implementation state

On master, committed and verified. `ui/framework.js` carries one shared pad
layer, `LexeditorUI.gamepadNavigation`, installed by the framework itself, so
every page that mounts the shared UI gets it: Home, every plugin editor,
Settings, dialogs and the Data Map. No plugin needed a change.

- D-pad and left stick move focus between tabs, list rows, fields and buttons,
  nearest-first and preferring the control beside the current one. A held
  direction repeats, immediately and then at a steady rate.
- A activates the focused control; on a text field it focuses the real input,
  selects the value and asks for the on-screen keyboard; on a bounded control
  left/right change the value instead of leaving it, with the same `input` and
  `change` events a typed edit sends.
- B closes what owns the screen (a shared dialog, a project menu, a rename
  editor, Home's own modal) and leaves a field being edited rather than
  discarding it; with nothing open it is the shell's own Back.
- Bumpers change tabs; triggers change page.
- The highlight is a `.lex-pad-focus` ring, because a programmatic `focus()`
  does not always light `:focus-visible`; it clears on the mouse, keyboard or
  a scroll.
- Nothing runs while no pad is attached, a pad that throws cannot break the
  page, and `uninstall()` removes every listener and timer.

Two shared surfaces had no keyboard way out and were repaired as part of this:
`showAlert` answers Escape, and a hand-built dialog that only offers a button
is dismissed through its Close/Cancel/Back/Dismiss action.

## Evidence

- `tests/shared/test_gamepad_navigation.py`, 7 checks: movement, activation,
cancel and Back, tab and page changes, number/slider/select stepping with
clamping, text entry asking for the keyboard, a held direction repeating, a
throwing pad, the real `mountShell` shell, and the real Home page (a card opens
its game, the settings button opens the settings panel).
- The checks drive the pad through `tick(now)` and through the real
`navigator.getGamepads` path; no hardware is needed and nothing is claimed
from a source reading.
- `tests/shared` and `tests/ff8` run green with it (the only shared failures at
the time were other lanes' in-flight work and the pre-existing DS3/tModLoader
ReShade loader-location failure).

## Next work

Needs a pushed candidate before Lexer can accept it on a Deck. Remapping,
rumble and a controller legend in the shortcut panel are not built and were
not asked for. On real hardware the on-screen keyboard depends on Steam's own
keyboard following focus; the virtual-keyboard API is called where the page
has it.
