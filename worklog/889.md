## 2026-10-13: 0.1.0 did nothing in game (fixed in 0.1.1)

Lexer's report: "does nothing". Cause: 0.1.0 hooked the CALL at 0x39761A,
which is gated on `[rsp+0x42]` (getter 0x1A4F60) and calls 0x391230, the
two-hand toggle request (writes pad+0x1C8 = 1/3). The island only ran on
the frame the two-hand button was pressed. The lab harness called the
island directly, so it could never see this.

0.1.1 calls the island from 0x39757C instead (`mov rax, rsi; lea rcx,
[rbx+0xf0]`, 10 bytes -> CALL + 5 NOPs; the island performs both before its
epilogue). Both commit paths join at 0x39756E and fall through, so it runs
every frame, before the held-duration loop (rerouted presses now get hold
time). Pad = caller RBX, controller = caller RDI, all volatiles dead.
Later-Game Ammunition keeps 0x397577 (the call just before); the loader's
same-instruction refusal is unchanged and the two compose (new test).
Unwind info is now DWORD-aligned (offset 896; 0.1.0 used 895).
`weaponCategory` at +0xE2 of the 0x110-byte row is confirmed from paramdef.
Package suite 17/17, harness 22/22 (now via a trampoline that mirrors the
hook site's registers).

## Design (verified statically)

One stateless island (see above for the hook site). Each frame it checks local player, HP, inhibit flag,
context, UI state, right-hand weapon kind 8 (catalysts, talismans, flames,
read from the installed params via the plugin's own reader) through the
native resolver, and saved/actor assembly agreement. It writes the selected
attunement index to EquipMagicData+0x78 (the same field the game's own
spell-switch writes) and reroutes R2/L1/L2 through the native weak-action
pad bytes; bare R1 only reselects. Native left/right admission gates are
mirrored, so unadmitted presses pass through untouched.

Hook bytes, call target and register setup were read back from the
fingerprinted executable (size 50286344, sha256 a45aaa36…) at build time.
The site differs from Later-Game Ammunition's, so the two compose.
