## Requirements (from the issue)

- Inspect the DS2/DS3 bonfire warp UIs and identify the clearer pattern.
- Recreate it in DS1; preserve destinations, unlock conditions, selection,
  travel; keep it behind a tweak (vanilla when disabled).

## Design (settled)

DS1 draws 21 destinations as one flat list in `Place_name_` ID order
(`FrpgMenuDlgWarp`, DRB `F09-06`, 11 rows; see `codex/ds1/warp-menu.md`).
DS3 groups one list by location (location tabs); DS2 picks area then
bonfire in a two-pane screen. Neither UI transfers as files: DS3 keeps
the same dialog classes but packs menus in encrypted BDTs, and DS2 uses
an unrelated menu framework. The pattern that fits DS1's flat widget is
DS3's: grouped by area with the area always shown.

Delivered as one dual mod, `warp-ui-rework` in the DS1 library
(disabled): a native tweak reorders the 21-record table by area in
journey order (one 14-byte hook at `0x6ED7C6` onto a data-only island;
records byte-identical, so unlock/skip/selection/confirm/travel run
their vanilla paths), and the data half renames the six ambiguous
destinations with their area in parentheses. Full header rows need
cursor/confirm rework and in-game iteration; tracked as follow-up.
