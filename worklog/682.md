## Binder rebuilds

`formats.pack(template, items)` rebuilds a BND3 from the template's
entry order, ids and stored names with new member bytes, laid out as
the game ships them (names tight, lazy 16-byte payload alignment,
empty members taking no space, no trailing pad). `members()` now
reports an undecodable name as FormatError instead of crashing the
merge. `_compose_anibnd` merges resized members through the rebuild
and keeps the in-place splice for same-size swaps; only added or
removed members still fall back to whole-file last-wins.

No OSS code was vendored for this: soulstruct was the candidate, but
the layout was fully measurable from the shipped files (offsets,
padding and the empty-marker rule over 217 binders), so the builder
is 40 lines pinned to measured data with no new license to record.

Tests: `test_ds1_binder_rebuild.py` (6: byte-identical rebuild,
resized round-trip with id stability, set-change rejection,
undecodable-name FormatError, two-mod resized merge, resized
conflict last-wins); all 7 existing `test_ds1_tae_merge.py` tests
unchanged and green. Fixture `build_anibnd` now emits real-shaped
16-aligned binders. Full `tests/ds1`: 568 passed, 13 skipped.
Live-install proof (read-only scratch probe, since deleted):
208/208 readable binders rebuild byte-identically (9 skipped are
the known-unreadable ones), a resized real binder re-parses with
every payload exact and passes deployment's soundness check, and an
end-to-end resized two-mod merge on real `c0000.anibnd.dcx` applies
both members with no conflicts.
